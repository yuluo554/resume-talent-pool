# resume-talent-pool 技术报告

> 简历解析与人才库管理桌面应用：解析方案 · 实体归一算法 · 合规设计。
> 版本 v0.1.0（2026-10-06）。本文档由 [scripts/make_report_docx.py](../scripts/make_report_docx.py) 程序化生成 docx 版（禁止手改产物）。

## 1. 摘要

本项目面向中小团队 HR 的简历沉淀与筛选场景，交付一款 **Windows 桌面应用**：简历批量导入解析（PDF/docx/txt → 结构化参数卡）、本地人才库（SQLite + FTS5 全文检索）、**同一候选人多版本简历识别与合并**（实体归一）、JD 硬条件初筛（三态命中矩阵）、隐私合规功能化（默认脱敏、一键清除、PIPL 说明页）。

核心结果（内置基准，固定 seed=20261005，全量 178 份合成简历）：

| 指标 | 结果 | 门槛 |
|---|---|---|
| 字段解析宏平均 F1 | 1.0000 | ≥ 0.95 |
| 同一人识别精确率 P | 1.0000 | ≥ 0.95 |
| 同一人识别召回率 R | 0.9583 | ≥ 0.95 |
| 误合并率 | 0.0000 | = 0（硬门槛） |

全部评测零 API 依赖、纯规则通路，固定输入两次运行输出逐字节一致；基准数据由合成简历生成器程序化生成并自带逐文件真值。

## 2. 系统架构

分层架构，核心域为纯函数库：

| 层 | 模块 | 职责 |
|---|---|---|
| GUI 层 | gui/（PySide6） | 五页面：导入、人才库、详情时间线、JD 初筛、合规与设置 |
| 服务编排层 | pipeline、storage | 导入流水线状态机、SQLite 持久化与检索 |
| 核心域 | parsing / normalize / screening / core | 解析、实体归一、JD 判定、参数卡 schema 与脱敏规则（纯函数，不碰 GUI/DB） |
| 评测层 | evaluation/ | 合成简历生成器 + 基准对账脚本 |

分层纪律：基准脚本直接调用核心域纯函数，保证"评测的就是业务本体"；GUI 只做展示与交互；CLI 与 GUI 共用同一服务层。全流程本地运行、零网络上传（可选 LLM 兜底为独立 extras，默认关闭且显式提示数据外发）。

## 3. 解析方案

### 3.1 管线

五步管线：文本化（按扩展名分派解析器）→ 行规整（CRLF 归一、全半角、伪空格清理，保留原始行号）→ 槽位抽取（每字段一条规则：正则 + 合法性校验 + 置信度）→ 置信度评分 → 参数卡输出。

### 3.2 关键设计

1. **证据防幻觉**：每个字段值必须携带证据（来源文件 + 原文摘录 + 位置），摘录必须是原文连续子串并有回归测试硬校验（`snippet is verbatim substring`）；无证据的字段置信度压到 0.5 以下并写入 warnings。
2. **PDF 空格保真（实测驱动）**：pdfplumber 的 `extract_text` 会把双空格折叠成单空格（语义不可逆），因此不走该接口，改从 `page.chars` 按行坐标聚合、逐字重建文本（空格数量保留），再走统一清理。生成器侧约定：合法分隔画双空格、伪空格画单空格，判别规则为"左侧 CJK 的孤立单空格即伪空格，2+ 空格折叠为一个分隔符"。
3. **词典切分兜底（实测驱动）**：中文 PDF 渲染中 U+00B7（·）为零宽字符，`技能：A·B·C` 抽取后熔断为无分隔长串（实测 71 份 PDF 中 18 份命中）。对策：以冻结参数池生成技能/证书词典，整行最长匹配切分；片段仍是原文连续子串，词典只用于已渲染文本切分，不引入原文外值。
4. **docx 表格简历**：正文流（段落与表格交错序）遍历，两列表格行序列化为"标签：值"伪标签行参与标签匹配；行号取正文流序列号，证据摘录取该行原文。
5. **工程陷阱覆盖**：GBK 编码探测、全半角数字归一、多行经历区块按行邻近聚类、中文路径全链 pathlib、CRLF 残留——每项有端到端样例断言。

### 3.3 置信度语义

标签与格式双确认 ≥0.9；仅格式命中 0.7；推断值 ≤0.5 并写 warnings；缺失字段不出现在真值与预测中（真值缺失字段被预测出来按 FP 计，防"蒙"刷分）。

## 4. 实体归一算法（核心）

### 4.1 三层证据

| 层 | 证据 | 强度 |
|---|---|---|
| 键1 精确 | 归一化后手机号或邮箱完全相等 | 决定性（直接同人） |
| 键2 姓名 | 全等 / 同音（拼音全拼 + 首字母键） | 弱（单独不可判同人） |
| 键3 经历 | 公司集合 Jaccard + 时间跨度重叠率 | 中强 |

### 4.2 评分与三档决策

综合分 `S = 0.4×姓名匹配 + 0.4×经历重叠 + 0.2×其他字段一致率`：

- S ≥ 0.85：自动合并；
- 0.6 ≤ S < 0.85：**待人工确认**（输出冲突字段清单，不硬判）；
- S < 0.6：判不同人。

**经历重叠定义（实测定稿）**：`0.4×公司集合 Jaccard + 0.6×时间跨度重叠率`，公司集合不相交时直接记 0。时间跨度取全部经历区间的并集交并比（相邻月连续、重叠区间合并、开放端记统一时间基准保证确定性）。理由：多版本简历"经历追加"会单向稀释 Jaccard，0.4/0.6 配比能把"追加经历 + 换联系方式"的常见演进形态压进自动合并档，同时"同名 + 共公司陌生人"的时间重叠天然存在、不构成同人证据，公司不相交即 0 使其评分上限落不进自动档。

**防误合并 over-rule（优先级高于评分）**：姓名相同（或同音）但双方手机号/邮箱均存在且互不相同、且经历零重叠 → 强制判不同人。同名不同人是基准显式植入项（5 组），误合并率目标 0。

### 4.3 合并策略

字段取值按简历时间取最新版本（仅历史版有的字段作为回填候选）；两版本对同一字段均有值且不等 → 落待确认记录，不硬判；历史参数卡全量归档（时间线视图由此渲染），合并只改主档不删数据。

### 4.4 指标

全量 178 份 / 100 真值组：P = 1.0000、R = 0.9583（TP 92 / FP 0 / FN 4）、聚类 F1 0.9787、**误合并率 0**。4 对未自动合并的同人多版本全部落在 0.6 ≤ S < 0.85 待人工确认档（联系方式更换/缺失 + 在职经历追加的演进形态），产品语义即"不自动合并、进人工队列"，不计为错误；9 对待确认对全部同类、零跨组。召回余量论证：压低阈值虽可再收 1 对，但会把同名共公司陌生人的自动合并风险窗口从 0.85 放大到 0.72，不换。

## 5. 合规设计（PIPL 功能化）

把《个人信息保护法》（2021-11-01 施行）的目的限定与最小必要原则落成可演示的产品功能：

1. **全本地存储、零上传**：SQLite 单文件 + 原件副本目录，GUI 内零在线资源引用（断网可演示）。
2. **默认脱敏显示**：手机号 `199****0003`、邮箱 `z******3@example.com`；settings 全局开关，显示与导出同约束，状态栏常驻指示。
3. **一键清除**：输入确认词二次确认 → 清空业务表 + FTS 表 + VACUUM + 删除导入原件副本，回显删除计数；JD 条件与脱敏设置为有意保留项并在合规页文案明示。
4. **启动首页即合规声明**：PIPL 白话说明、数据存储位置展示、免责声明（辅助筛选定位，非录用决策工具）。
5. **删除顺序满足外键约束、VACUUM 前 commit**，清除模块为纯执行层（可独立测试）。

## 6. 内置评测基准

- **合成简历生成器**：固定 seed，按人群模板（应届/社招技术/社招职能）批量生成 PDF/docx/txt（约 4:4:2），程序化植入已知关系——同一人多版本（约 60% 人有 2+ 版本）、5 组同名不同人、字段缺失（10–30%）、格式噪声（约 50% 文件）——并输出逐文件真值 JSON。
- **逐字节可复现**：随机性全走按实体派生的字符串种子流、禁用系统时间；PDF 用 invariant 模式、docx 落盘重写 zip 条目时间戳 → 同 seed 两次生成产物逐字节一致（基准与 CI 依赖此性质）。
- **对账口径**：解析按字段级 P/R/F1（宏平均）；归一按文件级聚类对账（预测合并对 vs 真值同人对），误合并率 = 跨真值组合并对占预测合并对比例。
- 指标见 §1 表；基准命令与 README 公开可复现。

## 7. 工程实践

- **测试**：152 项离线测试（解析/归一/存储/初筛/隐私/GUI 真实窗口/CLI/打包红线断言等），分批可跑；CI 四矩阵（ubuntu/windows × py3.8/3.11）全绿。
- **发布审计**：脱敏审计脚本随仓可复跑（跟踪树/全历史/提交信息三模式 + 阳性对照自检），发布门全 0。
- **打包**：PyInstaller onedir + zip（含 PySide6 与 PDF 解析链，zip 约 76MB），无 Python 环境冒烟通道（导入→检索→初筛→清除全流程自检并出报告文件）。
- **桌面端纪律**：后台导入走工作线程 + 回调；测试无模态对话框（可注入通知通道）；offscreen 渲染入 CI。

## 8. 边界与免责

- 输入仅限**文本型** PDF/docx/txt（扫描件图片型不支持，显式提示）；简历全部为合成数据（人名/手机号/邮箱虚构，手机号统一 199 假号段、邮箱用保留域）。
- 不做：简历爬取、背景调查、面试评价、云同步与多用户。
- **免责声明**：本工具仅辅助简历整理与筛选定位，不构成录用决策建议；使用者应自行确保对个人信息的处理符合适用法律法规。
