## 2. 用户与场景

- **用户**：中小团队 HR / 招聘运营个人用户，单机使用，非技术背景。
- **典型场景**：周一早上把邮箱导出的 30 份简历拖进导入页 → 人才库自动去重合并同一人 → 搜索"Java + 本科 + 3 年以上"得到候选列表 → 对某 JD 一键初筛出命中矩阵 → 发现"张三"有两个版本简历，系统提示待确认合并 → 处理完导出候选名单。全程断网可用、数据不出本机。

## 4. 边界与非目标（防 scope 失控）

继承 01 §六，开发期再补充：

- **不做**：真实简历采集（全部合成，人名/手机号/邮箱虚构）；招聘网站爬取；背景调查；面试评价；录用决策建议（辅助筛选定位，报告带免责声明）；OCR/扫描件图片型 PDF（输入仅限文本型 PDF/docx/txt，扫描件显式提示不支持）；简历模板美化或改写；邮件/消息发送；多用户账号与权限；云同步/多设备。
- **隐私红线**：本地 SQLite、零网络上传、默认脱敏显示、可一键清除。
- **品牌隔离**：不复制系列姊妹项目代码；文档不提建造/电力/医疗/招投标/食品/财务业务。
- **合成数据纪律**：手机号统一 19900000000 段假号，邮箱用 example.com 类保留域，脱敏审查白名单登记。

## 5. 与系列方法论的映射（内部备注）

解析层沿用"规则优先 + 统一中间表示"（本项目的中间表示 = 候选人参数卡）；实体归一是本系列首次引入的**跨文档实体对齐**变体（前六项目的比对是同域两文档对齐），核心算法风险集中在 M3/M4；LLM 仅兜底；基准先行定门槛；交付形态从 Web 换成 PySide6 桌面 + PyInstaller（沿用⑥财务项目的桌面经验）。
