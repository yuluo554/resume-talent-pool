## 1. 候选人参数卡 schema（统一中间表示）

```json
{
  "schema_version": 1,
  "source_file": "output/resumes/p03_r01_v2.pdf",
  "file_type": "pdf",
  "file_sha256": "…",
  "parsed_at": "2026-10-05T12:00:00",
  "fields": {
    "name":              {"value": "张三", "confidence": 0.95, "evidence": [{"source_file": "p03_r01_v2.pdf", "snippet": "姓名：张三", "location": "L3"}]},
    "phone":             {"value": "19900000003", "confidence": 0.95, "evidence": [{"…": "…"}]},
    "email":             {"value": "zhangsan3@example.com", "confidence": 0.95, "evidence": […]},
    "degree":            {"value": "本科", "confidence": 0.9, "evidence": […]},
    "school":            {"value": "示例理工大学", "confidence": 0.85, "evidence": […]},
    "major":             {"value": "计算机科学与技术", "confidence": 0.85, "evidence": […]},
    "graduation_date":   {"value": "2022-06", "confidence": 0.8, "evidence": […]},
    "desired_position":  {"value": "Java开发工程师", "confidence": 0.7, "evidence": […]}
  },
  "experiences": [
    {"company": "示例科技", "title": "Java工程师", "start": "2022-07", "end": "2024-08",
     "confidence": 0.8, "evidence": [{…}]}
  ],
  "skills":       [{"value": "Java", "confidence": 0.9, "evidence": […]},
                   {"value": "MySQL", "confidence": 0.9, "evidence": […]}],
  "certificates": [{"value": "CET-6", "confidence": 0.85, "evidence": […]}],
  "warnings": ["graduation_date 为推断值"]
}
```

**字段语义（既定口径，基准对账依赖）**：

- 日期统一 `YYYY-MM`；不确知的端点为 `null`（进行中工作 `end=null`）。
- `degree` 枚举归一：`大专/本科/硕士/博士/其他`（"研究生"归硕士，落 warnings 记录原文）。
- `confidence ∈ [0,1]`：标签+格式双确认 ≥0.9；仅格式命中 0.7；推断 ≤0.5 并写 warnings；缺失为 null（字段键可缺省）。
- `evidence[].location`：txt/docx 用行号 `L<n>`，PDF 用 `p<页>/L<行>`；`snippet` 必须是原文的连续子串（防幻觉硬校验）。
- 解析结果必须可从参数卡 + 原文件复核：任何 value 无 evidence 的字段置信度记 0.5 以下且进 warnings。

对应实现：`src/resume_talent_pool/core/card.py`（dataclass + to_dict/from_dict，骨架期已落）。

## 2. 解析层详设（M2）

管线五步（`parsing/`）：

1. **文本化**：pdf → pdfplumber `extract_text`（保留页/行序）；docx → 段落+表格遍历；txt → utf-8/gbk 探测读取。
2. **行规整**：CRLF 归一；全角数字/字母→半角；**伪空格清理**（单字符间孤立空格压缩——PDF 逐字定位导出的经典坑）；保留原始行号用于证据定位。
3. **槽位抽取**（每字段一条规则：正则 + 合法性校验 + 置信度，规则库 JSON/模块化可回归）：
   - phone：`1[3-9]\d{9}` 及分隔符变体（199-0000-0000），校验段位；
   - email：简化 RFC 正则；
   - degree：枚举关键词匹配；
   - school：`XX大学|XX学院|XX学校` 后缀模式；
   - graduation_date：`20XX年X月毕业` / `毕业时间：`标签；
   - experiences：区块头（工作经历/实习经历/项目经验）切分 → 条目内"公司/职位/起止时间"槽位聚类（**多行标注按行邻近合并**）；
   - skills：技能区块 + 分隔符（、，,/ | ·）切分，归一大小写；
   - certificates：证书区块 / 关键词（证书、资格证、CET）；
   - desired_position：`期望职位|求职意向` 标签行。
4. **置信度评分**：见 §1 语义。
5. **LLM 兜底（可选，P2）**：仅对缺失/低置信字段；只送含关键词/数字的压缩行（控成本）；要求"字段+逐字摘录"，摘录不是原文子串即丢弃；数值合法性校验；LLM 不可达直接降级规则通路。

**工程陷阱清单（M2 验收对照）**：PDF 伪空格、多行经历聚类、docx 表格简历、全半角混用、GBK txt、中文路径（全链 pathlib）、CRLF 残留、reportlab 生成 PDF 的字体可抽取性（M1 生成器侧保证）。

## 3. 实体归一详设（M3，核心算法）

### 3.1 三层证据

| 层 | 证据 | 强度 |
|---|---|---|
| 键1 精确 | 归一化后 phone 或 email 完全相等 | 决定性（score=1.0，直接同人） |
| 键2 姓名 | 全等 / 同音（pypinyin 全拼+首字母键） | 弱（单独不可判同人） |
| 键3 经历 | 公司集合 Jaccard + 时间区间重叠率 | 中强 |

### 3.2 评分与三档决策

- 候选对生成：键1 命中，或键2 相似（全等/同音）进入 pairwise 评分。
- 综合分：`S = 0.4×姓名匹配 + 0.4×经历重叠 + 0.2×其他字段一致率`（学校/专业/期望职位；权重为初值，M4 基准上可调，调整须留档）。
- 三档：`S ≥ θ_auto(0.85)` 自动合并；`θ_manual(0.6) ≤ S < θ_auto` 进**待人工确认**队列（输出冲突字段清单）；`S < θ_manual` 判不同人。
- **防误合并 over-rule（优先级高于评分）**：姓名相同（或同音）但双方 phone/email 均存在且互不相同、且经历零重叠 → 强制不同人。同名不同人是评测显式植入项，误合并率目标 0。

### 3.3 合并策略

- 字段取值：按简历时间（生成时间/简历内最新经历端点）取**最新版本**的值；仅历史版有的字段值作为回填候选。
- 冲突：两版本对同一字段均有值且不等（phone/email/degree 等）→ `merge_conflicts` 表落一条待确认记录，不硬判。
- 版本：所有历史参数卡归档（`resumes` 表），时间线视图由此渲染；合并只改 candidates 主档，不删数据（与一键清除的"真删除"区分）。

## 4. JD 硬条件初筛详设（M3）

```json
{
  "jd_id": "jd001", "title": "Java后端（3-5年）",
  "degree_min": "本科",
  "years": {"min": 3, "max": 5},
  "must_have_skills": ["Java", "MySQL"],
  "exclude_keywords": ["培训机构"] 
}
```

- 每候选人逐条判定，**三态**：`hit` / `miss` / `insufficient`（该字段缺失或证据不足 → 显示"待人工确认"，不硬判；这是防幻觉口径在初筛的延伸）。
- 学历门槛按枚举序比较；年限 = 工作经历区间并集跨度（重叠区间合并后计算）；技能命中 = 技能标签包含（大小写归一）。
- 匹配分（排序用）：`0.6×必备技能命中率 + 0.2×年限符合 + 0.2×学历符合`；硬排除项命中直接标记排除。
- 输出：命中矩阵表（候选人 × 条件）+ 排序列表 + 逐条证据（命中依据字段与其 evidence）。

## 5. 存储层表结构草案（M3 定稿）

```sql
candidates(id PK, name, name_py, phone, email, degree, school, major,
           graduation_date, desired_position, latest_resume_id,
           years_of_work REAL, created_at, updated_at)
resumes(id PK, candidate_id FK, source_file, file_type, file_sha256 UNIQUE,
        resume_date, card_json, parsed_at)          -- 参数卡全量归档
experiences(id PK, resume_id FK, candidate_id FK, company, title,
            start_month, end_month)
tags(id PK, name UNIQUE, kind)                        -- kind: skill|source|custom
candidate_tags(candidate_id, tag_id, PRIMARY KEY(candidate_id, tag_id))
merge_conflicts(id PK, candidate_id, field, option_a, option_b,
                chosen, status, created_at, resolved_at)
jd_requirements(id PK, title, condition_json, created_at)
settings(key PK, value)                               -- 脱敏开关等
-- FTS5：candidates_fts（name/skills/school/major/company，trigram）
--     内容同步策略 M3 定稿（触发器 vs 应用层双写）
```

`file_sha256 UNIQUE` 兼做导入去重。库文件默认位置：`%APPDATA%/resume-talent-pool/`（启动页展示实际路径，合规页可跳转）。

## 7. 评测模块详设（M4）

- `benchmark_parse`：对全量合成集跑解析，字段级 P/R/F1（预测值归一后与真值比对；**真值缺失的字段被预测出来计 FP**，漏计 FN），宏平均报告；目标 F1 ≥ 0.95。
- `benchmark_match`：同一人识别按组聚类对账：组内两两对 vs 预测合并对 → P/R；误合并率 = 跨真值组合并的文件对占预测合并对比例（M4 定档口径见 D-024），目标 0。
- 输出 markdown 指标表直贴 README；全程零 API 依赖（纯规则通路）；固定 seed 复现：两次运行输出逐字节一致（时间戳字段除外，真值与指标不含时间戳）。
